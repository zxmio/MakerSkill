# 财务仪表盘（finance-dashboard）

把微信和支付宝的原始账单，变成一张看得懂的财务全局图：钱从哪来、花在哪了、哪块能省。

产出两页，装在同一个 HTML 文件里：

- **仪表盘**：四个核心数（总收入、总支出、结余与储蓄率、日均支出）、月度收支（支出按分类堆叠，收入是折线）、支出构成环形图、分类 × 月份明细表、花钱最多的商户、每月固定支出、最大单笔、消费时段、一周分布、收入来源。
- **洞察报告**：一句话结论、四个健康指标、三到五条关键发现、三到四条行动建议。

数字由脚本算，判断由 AI 写。脚本负责「准」，AI 负责「懂」。

## 铁律

1. **账单不出本机。** 不上传到任何网站、图床、云端模型以外的服务，不贴进公开仓库。产物默认放在账单所在文件夹的 `财务仪表盘/` 子目录里。
2. **洞察里每个数字都要能追溯。** 只能来自 `analysis.json`，或者用 Python 对 `transactions.csv` 现算出来的结果。算不出来的不写，绝不估一个「大概」。
3. **先补归类，再写洞察。** 「其他」占支出超过 5% 时，先补规则重跑，否则结论会偏。
4. **工资进银行卡的，收入会严重偏低。** 一定先问清楚，再决定是否手动补录。不问就算储蓄率，结论可能是反的。
5. **不训人，不贩卖焦虑。** 用户花钱是他的自由，洞察只呈现事实和可选的调整，语气像一个帮你看账的朋友。

## 流程

### 第 1 步：拿到账单

用户还没导出的，把 `references/export-guide.md` 里对应平台的步骤发给他。要点：

- 微信、支付宝导出的都是**加密压缩包**，密码在 App 的消息里（微信支付公众号、支付宝消息）。让用户自己解压，或者给你密码后用 `unzip -P <密码> <文件> -d <目录>` 解压。
- 解压出来的文件放进**同一个文件夹**。多次导出、两个平台混在一起都没关系，脚本按交易单号去重。

### 第 2 步：问清三件事

能从上下文推断的就不问，问也一次问完：

| 问什么 | 为什么 |
|---|---|
| 工资或主要收入是否走银行卡？每月大概多少？ | 不在账单里的收入要手动补录，否则储蓄率失真 |
| 房租、房贷有没有走银行卡直接扣？ | 同理，大额固定支出漏掉会让支出偏低 |
| 看哪段时间？仪表盘标题里怎么称呼你？ | 默认全部账单时间；称呼可以不填 |

### 第 3 步：跑分析

```bash
python3 ~/.claude/skills/finance-dashboard/scripts/analyze.py <账单文件夹> --out <账单文件夹>/财务仪表盘 [--from 2026-01] [--to 2026-10] [--name 称呼]
```

脚本只用 Python 标准库。它会：

- 自动识别微信（xlsx / csv）和支付宝（新版、旧版 csv，GBK 编码）的格式
- 按交易单号去重
- 排除不该算的：信用卡和花呗还款、余额宝和零钱通、提现充值、已关闭和全额退款的交易；部分退款从原支出里扣掉
- 按内置规则归类（`scripts/rules.json`），支付宝自带的「交易分类」作为兜底

产出三个文件：

| 文件 | 内容 |
|---|---|
| `analysis.json` | 所有汇总数字，写洞察的唯一事实来源 |
| `uncategorized.md` | 归到「其他」里金额最大的商户清单 |
| `transactions.csv` | 每一笔交易的归类结果，用户可以自己核对 |

把终端输出的摘要（笔数、收入、支出、不计入金额、未归类占比）先报给用户。

### 第 4 步：补归类

读 `uncategorized.md`，根据商户名和商品说明判断类别，写到输出目录的 `rules.local.json`：

```json
{
  "merchants": { "杭州某某商贸有限公司": "shopping", "设计客户A": "business" },
  "keywords": { "猫粮": "other" },
  "manual": [
    { "month": "每月", "kind": "income", "category": "salary", "name": "工资（银行卡）", "amount": 16000 },
    { "month": "2026-03", "kind": "expense", "category": "housing", "name": "房贷", "amount": 6200 }
  ]
}
```

- `merchants` 按交易对方精确匹配（也匹配商品说明里包含这个名字的），`keywords` 按关键词匹配，都优先于内置规则。值写 `"excluded"` 表示不计入。
- 支出类别：`dining` 餐饮美食、`groceries` 日用超市、`shopping` 网购购物、`transport` 交通出行、`housing` 居住缴费、`digital` 数字订阅、`entertainment` 休闲娱乐、`travel` 旅行住宿、`health` 医疗健康、`learning` 学习成长、`social` 人情往来、`other` 其他。
- 收入类别：`salary` 工资薪酬、`business` 经营收款、`transfer_in` 转账红包、`other_income` 其他收入。
- **收到的转账要过一遍。** 微信转账收入默认算「转账红包」，但其中可能是副业收款、报销、AA 回款。看 `transactions.csv` 里金额较大的转账收入，拿不准的问用户。
- `manual` 补录账单之外的收支，`month` 写 `每月` 表示账单覆盖的每个月都记一笔。

带上规则重跑：

```bash
python3 ~/.claude/skills/finance-dashboard/scripts/analyze.py <账单文件夹> --out <输出目录> --rules <输出目录>/rules.local.json
```

「其他」降到 5% 以下就够了，不用追求零。

### 第 5 步：写洞察

先读 `references/insights-guide.md`，再读 `analysis.json`。需要更细的数字（某个商户上下半年对比、某个时段的笔数），用 Python 读 `transactions.csv` 现算，不要心算。

写到 `<输出目录>/insights.json`，字段和写法见指南。

### 第 6 步：渲染与交付

```bash
python3 ~/.claude/skills/finance-dashboard/scripts/render.py <输出目录> --png
```

产出 `finance-dashboard.html`（双击用浏览器打开，`#insights` 切到洞察页），加 `--png` 时再出 `dashboard.png`、`insights.png`（需要本机有 Chrome、Chromium 或 Edge）。

交付时：

1. 打开 PNG 自己看一遍，确认没有错位、没有空白卡片。
2. 在对话里用三五句话讲清楚最重要的结论，附上 HTML 和 PNG 的路径。
3. 提醒用户：产物里有完整消费明细，分享截图前看一下有没有不想公开的商户名。

## 没有账单，只想先看效果

```bash
python3 ~/.claude/skills/finance-dashboard/scripts/make_sample.py /tmp/finance-demo/bills
```

生成一套虚构的微信、支付宝账单（一位杭州上班族的 10 个月），格式和官方导出一致，从第 3 步开始走完整流程即可。

## 已知局限

- 银行卡直接消费、信用卡直接刷卡、现金都不在微信和支付宝账单里，只能手动补录。
- 两个平台之间互相转账（比如微信转到自己的支付宝）偶尔会两边各记一笔，发现了就在 `rules.local.json` 里把那个交易对方设成 `"excluded"`。
- 美团、抖音这类综合平台的商户名笼统，外卖、买菜、团购可能都叫「美团平台商户」，必要时按商品说明加关键词规则。
- 「每月固定支出」是按同一商户连续 3 个月以上、每月金额波动不超过 20% 识别的，不代表都是自动续费。
