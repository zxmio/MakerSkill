# 麦肯锡式表达 · 授课型组织工具箱（辅助）

> **定位（重要）：** 本文是**辅助工具箱**，不是主方法。授课型 PPT 的主方法是 SKILL.md 里的「零基础手把手」——每个知识点走「是什么→为什么→怎么做」，配强类比、没有它vs有了它、真实可照抄的路径/代码。下面这些结构（对比/流程/矩阵/并列）只在你需要**组织某一页信息**时按形态选用。**结构名永不上页**，也别让"结论金句墙"盖过"把概念讲到零基础也懂"。

把某一页信息组织清楚，常需要选对结构。本文每套结构标了「是什么 / 何时用 / 模板 / 怎么用 / 正反例」。

操作顺序：**金字塔定模块骨架 → SCQA 写开场 → MECE 给支撑分组 → 每页写 Action Title → 空雨伞/PREP/WWH 展开局部 → Storyline 自检。**

授课型 vs 路演型的一条总差异：**路演求"少而准"，授课求"密而清"。** 授课 PPT 兼做讲义和复习材料，每页在"一个论点"前提下要尽量信息完整（用表/框架/数据/案例撑），而不是一页一句话。

> **铁律：结构名只在本文和作者脑子里，绝不上页。** 下面所有结构（空雨伞 / MECE / SCQA / 金字塔 / PREP）只用来组织逻辑——页面文案里**不写方法名，也不写"空/雨/伞、S/C/Q/A"这类分段标签**，只把内容顺成自然的话呈现。学员看到的是结论和论据，不是方法论术语。

---

## 0. Action Title（行动标题）—— 灵魂

**是什么。** 每页标题是一句**完整的结论性陈述**（主谓宾俱全、能独立读懂），不是名词短语标签。所有页的 Action Title 顺次连起来，应是一条能独立成立的完整故事线（storyline）。

**判断标准。** 标题能回答"所以呢？（So what?）"；去掉这页的图表，只读标题也能 get 到结论。

**授课型怎么用。** 知识点页的标题也要是结论句，不是知识点名词。学员扫一遍标题就能复习全模块逻辑。
- 反例（名词标签）：`上下文工程` / `四层结构` / `背景介绍` / `三个要点`
- 正例（结论陈述）：`AI 不是不够聪明，是不懂你的项目` / `四层上下文让 AI 新会话就懂你的项目` / `改一处忘同步，是 AI 时代最大的隐性返工`

**自检。** 写完所有标题，单独抽出来读——连起来通顺有说服力，storyline 就立住了。

## 1. 金字塔原理（Pyramid · Minto）

**是什么。** 信息组织成金字塔：顶端一个中心论点（Governing Thought），下面几组理由，再下面论据/数据。四条铁律：结论先行 · 以上统下 · 归类分组 · 逻辑递进。

**何时用。** 定模块整体骨架时必用。回答"这个模块的核心主张是什么 / 用哪几组撑"。

**授课型怎么用。** 每个教学模块 = 一个中心论点 + 3 组（最多 7）知识点群。先定这个金字塔，再把每个知识点群展成页。模块小结页 = 重申金字塔顶。

**模板。**
```
模块中心论点（1 句结论）：________
├─ 知识点群 A：________（论据/真实案例）
├─ 知识点群 B：________（论据/真实案例）
└─ 知识点群 C：________（论据/真实案例）   ← 3 组最佳，≤7
```

## 2. SCQA（开场/导入）

**是什么。** S 情境（共识）→ C 冲突（变化/矛盾，制造张力）→ Q 疑问 → A 回答（你的主张 = 金字塔顶）。

**何时用。** 每个模块/每天开篇的钩子。

**授课型怎么用。** 用学员的真实痛点做 C（冲突），比泛泛背景更抓人。如"我们都在用 AI 写代码（S），但多人协作还是返工不断（C），为什么？（Q）——因为缺共享的上下文（A）"。

**模板。**
```
S：我们都________（共识）
C：但是________（变化/问题）
Q：那么________？
A：答案是________（主张）
```

## 3. MECE（分类质检）

**是什么。** Mutually Exclusive（不重叠）+ Collectively Exhaustive（无遗漏）。是"归类分组"的质检标准。

**何时用。** 每次把一件事拆成几个要点/维度时，都自检：有没有重叠？有没有漏？

**授课型怎么用。** 知识点分组、对比维度、实操步骤都要 MECE。学员对"穷尽感"敏感——漏了一类会觉得没讲透。

**常用切分。** 流程（before/during/after）、要素（人/货/场、前端/服务/数据库）、二分（内/外、主观/客观）、公式（利润=收入−成本）。

**经验。** 要点 3 个最佳，≤7（神奇数字 7±2）。

## 4. 空雨伞（事实 → 解读 → 行动）

**是什么。** 空（事实/现象）→ 雨（解读/判断）→ 伞（行动/对策）。

**何时用。** 讲真实案例、给建议、从现象推对策时。强制"先有事实再有判断，先有判断再有行动"。

**授课型怎么用。** 讲师真实项目案例最适合这个结构：先摆事实（真实 git log / 真实事故），再解读（说明什么），再给行动（团队该怎么做）。

**模板。**
```
空（事实）：我们观察到________
雨（解读）：这说明________
伞（行动）：因此应该________
```

---

## 5. PREP（单点展开）

**是什么。** Point（观点）→ Reason（理由）→ Example（例子）→ Point（重申）。把一个论点讲透、首尾呼应。

**何时用。** 一页之内论证一个点；展开金字塔某一组支撑时。

**模板。** P 我的观点是…… → R 因为…… → E 比如（真实案例）…… → P 所以……

---

## 6. What–Why–How（概念三段式）

**是什么。** 是什么 → 为什么 → 怎么做。介绍概念/方法/工具的朴素三段式。

**何时用。** 讲一个新概念，学员需"先懂再信再做"时。理念驱动的开场把 Why 前置更有感染力。

**授课型怎么用。** 知识点讲解页的默认结构。用一张三行表（是什么/为什么/怎么做）承载，比三段文字更密更清。

---

## 7. 信息组织的四种基本关系

排一组要点前，先想清它们是哪种关系——决定用哪种页型：

| 关系 | 含义 | 页型 |
|---|---|---|
| 并列 | N 个平级同类要点 | MECE 并列 / 2×2 矩阵 |
| 递进 | 层层深入、按时间推进 | 流程 / 金字塔 |
| 对比 | A vs B、现状 vs 目标 | 对比页 |
| 总分 | 先总后分 / 先分后总 | 金字塔 + 并列 |

---

## 速查：从"想表达什么"到"选哪个结构"

| 你要表达 | 用结构 | 页型 |
|---|---|---|
| 开篇引出、制造张力 | SCQA | SCQA 开场 |
| 抛模块核心主张 | 金字塔顶 | 中心论点页 |
| 结论 + 几组理由全貌 | 金字塔 | 框架/总览 |
| 几个平级维度（已 MECE） | 并列 + MECE | MECE 并列 |
| 两方案/状态差异 | 对比 | 对比页 |
| 两维度分类定位 | 矩阵 + MECE | 2×2 矩阵 |
| 从现象推到对策 | 空雨伞 | 案例/对策 |
| 介绍一个概念/方法 | What-Why-How | 概念页 |
| 一套有先后的步骤 | 递进/流程 | 流程页 |
| 动手任务 | 步骤化 | 实操页 |
| 收尾给行动 | 结论先行 | 小结页 |

---

## 授课型典型模块骨架（按内容取舍，不必都用）

```
封面 → SCQA 开场 → 中心论点 → 框架总览(金字塔)
     → 知识点群 A(概念WWH / MECE并列 / 对比)
     → 知识点群 B(空雨伞真实案例 / 流程)
     → 知识点群 C
     → 【实操】 → 小结(重申金字塔顶 + 衔接下一模块)
```

授课型比短视频 deck 多了【实操】和更密的知识点页；少了过度营销化的钩子，多了"可复习"的信息完整度。
