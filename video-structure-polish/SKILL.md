# 轻润色 + 逻辑重构

用户已经把想说的话说出来了（打字或语音转写）。这个 skill 不生产内容，分两步处理：

1. **轻润色** — 清理语音噪音，输出干净的完整稿，保持原文顺序
2. **逻辑重构** — 用 SCQAR 模型评估润色稿，主动向用户追问缺失环节，补齐后输出完整重构稿

核心原则：内容是用户的，你只是整理者。润色不改词，重构不改句——只调顺序和组合，缺的信息问用户要，不替用户编。

---

## 工作流程（两轮对话）

### 第一轮：润色 + 缺口追问

收到内容后输出两部分：

1. **轻润色完整稿** — 逐句轻修后的干净文章，保持原文顺序
2. **SCQAR 评估** — 用六步模型逐步对照润色稿，标注哪些步骤已覆盖、哪些缺失，然后针对缺失步骤向用户提出具体问题

第一轮结束时，等用户回答问题。

### 第二轮：逻辑重构

用户补充信息后，将润色稿的原句 + 用户补充的新内容，按 SCQAR 顺序组装成完整的逻辑重构稿。

如果用户表示某个缺口不需要补充（"这个不用说"），就跳过那个步骤，用现有内容直接重构。

---

## 第一部分：轻润色完整稿

"润色"在这里的定义非常窄，宁可改少，不可改多。

### 只做这四件事

1. **合并重复** — 连续或紧邻的重复词句只留一个。"然后然后我就" → "然后我就"；"特别特别好用" → "特别好用"；同一句话说了两遍留表达更完整的那遍
2. **删无语义的语气词和口头填充** — 嗯、啊、呃、哈、那个、就是说、对吧、这样子。判断标准：删掉后句子意思完全不变才删。承担语义的保留（"就是这个原因"里的"就是"不能删）
3. **调整标点和分段** — 断句、加逗号句号问号、按意思分段。段落偏短，一两句一段
4. **修正明显错别字** — 语音转写的同音字错误（"必竟"→"毕竟"）、明显打错的专有名词。拿不准的保留原样

### 绝对不做的事

- 不改写句子结构，不调整语序
- 不替换用词——用户写"贼好用"就保留"贼好用"，不改成"非常实用"
- 不增加任何内容：不加过渡句、不加小标题、不加总结收尾
- 不删实质内容——哪怕觉得啰嗦，只要两句话意思不同就都保留
- 不调整段落顺序——顺序调整是第二部分的事，润色稿忠实保持原文顺序

### 示例

原文：
> 然后就是我觉得这个东西啊，其实其实核心就是一个点，就是就是你得先把自己的东西给做出来，做出来之后呢，然后再去想怎么卖的事。

正确润色：
> 我觉得这个东西，核心就是一个点：你得先把自己的东西做出来，做出来之后，再去想怎么卖的事。

错误润色（改多了）：
> 这件事的核心在于：先完成产品，再考虑销售。 ← 换了用户的词，压缩了句子，不允许

### 输出格式

润色稿作为完整文章直接输出在对话里。

输出后加一行字数对比（原文 X 字 → 润色后 Y 字），让用户确认删减幅度在预期内。正常幅度是缩短 5%-15%；如果超过 20%，说明可能删多了，回头检查。但如果超出是因为语音转写噪音（重复句、识别错字）导致的，属于正常，注明原因即可。

## 第二部分：SCQAR 评估与追问

### SCQAR 模型（六步）

从麦肯锡 SCQA 扩展而来的经验分享型表达模型，适合"我做了一件事，来分享怎么做的"这类内容：

| 步骤 | 名称 | 要回答的问题 |
|------|------|-------------|
| S | 背景与成果 | 我在什么场景下做了什么，拿到了什么结果？ |
| C | 冲突与痛点 | 我为什么要做这件事？之前的状态有什么问题？ |
| Q | 问题根源 | 造成这个痛点的真正原因是什么？ |
| A | 解决方案 | 我的方案是什么？一句话概括 |
| R₁ | 解决过程 | 具体怎么做的？一步步展开 |
| R₂ | 最终结果 | 做完之后效果怎么样？和开头的成果呼应 |

### 评估方法

逐步检查润色稿，判断每个步骤是"已覆盖"还是"未覆盖"：

- **已覆盖** — 润色稿里有明确对应的句子。标注是哪些句子
- **未覆盖** — 润色稿里没有提到。准备一个具体的追问问题

### 追问规则

- 每个未覆盖的步骤对应一个问题，问题要具体，不要泛泛地问"能补充一下吗"
- 问题要帮用户打开思路，比如："之前公众号更新卡在哪里？是没时间写，还是写了但排版发布太麻烦？"
- 所有问题一次性提出，不要一问一答多轮追问
- 如果六步全覆盖，跳过追问，直接输出重构稿

### 输出格式（第一轮）

```
【轻润色完整稿】
（润色后的文章）
原文 X 字 → 润色后 Y 字

---

【SCQAR 评估】

✅ S（背景与成果）：已覆盖 — "xxx""xxx"
❌ C（冲突与痛点）：未覆盖
✅ A（解决方案）：已覆盖 — "xxx"
...

为了让逻辑更完整，想再了解几个点：

1. （针对 C 的具体问题）
2. （针对 Q 的具体问题）
...
```

---

## 第三部分：逻辑重构稿（第二轮）

用户回答追问后，将润色稿原句 + 用户补充的内容，按 SCQAR 六步顺序组装成完整文章。

### 重构规则

- **可以做的事：**
  - 从润色稿中摘取任意句子，放到它在 SCQAR 模型中最合适的位置
  - 将说同一件事的散落句子归拢到同一步骤下
  - 合并意思高度重叠的句子（两句话说的是同一件事，留更完整的那句）
  - 将用户补充的内容以用户的原话整合进对应步骤（做和润色稿一样的轻度清理：去重复、去语气词、修错字）
  - 为段落之间做最小限度的衔接词调整（如"所以"改成"而且"，因为因果关系在新位置不成立了）

- **不可以做的事：**
  - 不写新句子，不加任何用户没说过的内容
  - 不改变句子内部的措辞和用词
  - 不删除任何实质内容——润色稿和用户补充里的每个独立意思都必须出现在重构稿里
  - 不加小标题、不加过渡段、不加总结句

### 输出格式（第二轮）

```
【逻辑重构稿】

（按 SCQAR 顺序编排的完整文章）

---
调整说明：
- 具体说明 1（哪些内容归到了哪个步骤，做了什么调整）
- 具体说明 2
- ...
```

调整说明 2-4 条，每条说清楚做了什么、为什么。

超过 1500 字时，同时存一份 .md 文件到 /mnt/user-data/outputs 并用 present_files 给出。
