# 会议精华稿（meeting-digest）

把一份**多人会议/咨询/沟通的转写记录**，提炼成一篇**结论导向、按主题归纳、纯文本可直接对外**的精华稿（`.md`）。

核心区别（别做混了）：

- **逐字稿** = 清洗版全文，保留每个人的完整发言，按说话人分轮。用于存档、回溯原话。
- **会议精华稿（本技能）** = 只提炼"结论/决策/共识/下一步"，按主题重组，不逐句复述。用于决策、对外同步、快速回顾。
- **直播精华稿** = 直播单人讲课 → 第一人称润色长文 + 配图。场景不同，别用本技能。

## 端到端流程（4 步）

1. **通读 + 认人 + 去噪**：读完整篇转写。识别说话人身份（谁是主咨询/谁是客户/谁是跟进），并丢弃与主题无关的噪音——寒暄、拍照、加微信、行程闲聊，**转写结尾尤其常见串台**，识别后直接略去（可在文末用一行说明"此后为……闲聊，略"）。
2. **抽取结论**：边读边把"达成的诊断、共识、决策、判断、下一步动作"挑出来。只要**结论性**内容，丢弃过程中的来回试探、重复确认、口水。
3. **按主题重组**：把抽出来的结论**按主题聚类**（而不是按时间顺序），每个主题一个小节。一次会议通常 5–9 个主题。给每个主题起一个能点出结论的小标题。
4. **按模板成稿**：套用下方「输出模板」，每节用加粗的核心结论领起 + 要点列表展开，最后给一句话总结。写到与源转写同目录的 `<主题>-精华稿.md`。

## 提炼规范（决定成稿质量）

- **结论导向，不复述过程**：写"双方定下要做什么、为什么、判断是什么"，不写"A 说了 X，B 回应 Y"。读者要的是结果，不是对话回放。
- **忠于原意，不编造**：所有结论、数字、案例必须来自转写原文。**不要替谁补充新观点、新数据、新方案。** 拿不准的宁可不写。
- **保留关键原话与比喻**：会议里那些一针见血的金句、比喻、真实数字（如"卖零件不是卖汽车""10 小时降到 2 小时""一年服务 15–20 个客户"）要保留，它们是结论的锚点。
- **每节结构**：小标题点结论 → 一句话或加粗句给出该主题的核心判断 → 下面用 `-` 列表或 `1. 2. 3.` 展开支撑要点。
- **抓"转折/共识/决策"信号**：留意"所以我建议""我们定下来""核心是""本质上是""下一步""先……再……"这类句子，结论往往就在这里。
- **分歧也要记**：如果双方有不同意见或客户的保留/担心，单独点出来，别只写一边。

## 平台合规（重要，成稿要能对外）

精华稿默认要发给会员/同步给对方/进知识库，**正文一律纯文本化**：

- 禁止 Obsidian callout（`> [!info]` 等），禁止 emoji（标题/正文/列表都不放）。
- 需要"提示/注意/分歧/问答"时，用**加粗小标题领起的普通段落**（如 `**客户的保留：** ……`）。
- 可保留：加粗、行内代码、普通块引用 `>`、表格、列表、分割线。
- 例外：若用户明确说只在 Obsidian 内部用、不对外，可放宽。

## 输出模板

```markdown
# <会议主题> · 精华稿

本稿提炼自<时间/场景>的<会议类型>，记录双方达成的核心结论与下一步。参与人：<甲>（角色）、<乙>（角色）……

---

## 一、<点出结论的小标题>

<一句话或加粗句给出本主题的核心判断。>

- <支撑要点 1>
- <支撑要点 2>

## 二、<……>

……（按主题 5–9 节）

---

## 一句话总结

<把整场会议压成一句可执行、可记住的话。>
```

## 黄金范例（输入 → 输出）

本技能的参考样例（已在库内）：

- 输入（机器转写原文）：`01项目管理/01高客单业务/01-源头资料/泽宇顶层设计沟通记录.md`
  —— 800+ 行、带「说话人1/2/3 + 时间戳」、满是口水词与结尾串台的咨询转写。
- 输出（结论精华稿）：`01项目管理/01高客单业务/02-沟通整理/泽宇顶层设计沟通-精华稿.md`
  —— 七个主题小节（核心诊断 / 模式重构 / 人群 / 产品 / 销售获客 / 落地节奏 / 合作原则），每节加粗结论领起 + 要点列表，末尾「一句话总结」，全程纯文本。

成稿前可对照这两份文件校准粒度：**精华稿篇幅通常是转写原文的 1/8 到 1/15**，宁可精炼不要注水。

## 产出与约定

- 输出位置：与源转写**同目录**，命名 `<会议主题>-精华稿.md`。
- 若同一场会议还要别的产物：逐字稿叫 `<主题>-逐字稿.md`（清洗版全文）、个人复盘叫 `<主题>-我的复盘.md`（第一人称、沟通前后思维差异）。三者可共存、互补。
- 纯 `.md`、纯文本配图无关，可直接发公众号 / 进飞书知识库 / 发给对方。

## 踩坑

- **结尾串台**：转写结尾常混入拍照、加微信、行程/老家闲聊等无关内容，识别后略去，别写进结论。
- **别退化成纪要流水账**：纪要按议程罗列"谁说了啥"，精华稿要的是"结论是什么"。按主题聚类、结论领起，才是精华稿。
- **多人会议先认人**：先搞清每个说话人的身份和立场，否则容易把客户的疑问误当成顾问的结论。
- **中文文件名**在 zsh 下 glob 易报错，命令前先 `export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`。
