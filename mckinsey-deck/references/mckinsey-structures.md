# 麦肯锡表达结构库

把口播逐字稿改造成「结论先行、逻辑清晰」的演示,核心是先选对结构。下面是主流的几套结构,每套都标了「是什么 / 何时用 / 模板 / 正反例」。

实际操作顺序通常是:**先用金字塔原理定整体骨架 → 用 SCQA 写开场 → 用 MECE 给支撑论点分组 → 给每页写 Action Title → 用空雨伞/PREP/流程展开局部。**

---

## 0. Action Title（行动标题）—— 麦肯锡 PPT 的灵魂

**是什么。** 每一页的标题都是一句**完整的结论性陈述**(主谓宾俱全、能独立读懂),而不是名词短语标签。把所有页的 Action Title 顺次连起来,应该就是一条能独立成立的完整故事线(storyline)。

**判断标准。** 标题能回答"所以呢?(So what?)";去掉这一页的图表,只读标题也能 get 到结论。

**正反例。**
- 反例(名词标签):`市场分析` / `用户画像` / `三个维度` / `背景介绍`
- 正例(结论陈述):`三大趋势正在重塑这个市场` / `核心用户是 25-35 岁的城市白领` / `从时间、空间、同伴三处定位你的高效规律` / `问题不在自制力,而在你所处的环境`

**自检。** 写完所有标题后,把它们单独抽出来读一遍——如果连起来就是一段通顺、有说服力的话,storyline 就立住了。

## 1. 金字塔原理（Pyramid Principle · Minto）

**是什么。** 全篇信息组织成金字塔:顶端一个中心论点(Governing Thought),下面是支撑它的几组理由,再下面是论据/数据。四条铁律:
1. **结论先行** —— 先抛中心论点,再展开。
2. **以上统下** —— 上一层是下一层的概括,下一层是上一层的支撑。
3. **归类分组** —— 同组要点性质相同(配合 MECE)。
4. **逻辑递进** —— 组内按演绎(因为→所以)或归纳(并列同类)排序。

**何时用。** 决定整篇骨架时一定要用。它回答"我的核心主张是什么 / 用哪几组理由支撑"。

**模板。**
```
中心论点(1 句):__________
├─ 支撑理由 A:______（为什么成立:论据/数据）
├─ 支撑理由 B:______（为什么成立:论据/数据）
└─ 支撑理由 C:______（为什么成立:论据/数据）   ← 理由控制在 3 组,最多 7 组
```
对应版式:`governing`(中心论点页) + `pyramid`(结构总览页)。

## 2. SCQA（开场/导入结构）

**是什么。** 用四步把听众带入问题、引出你的主张:
- **S 情境 Situation** —— 大家都认同的背景/现状(建立共识)。
- **C 冲突 Complication** —— 打破平衡的变化、障碍或矛盾(制造张力)。
- **Q 疑问 Question** —— 由冲突自然引出的关键问题。
- **A 回答 Answer** —— 你的核心主张,正好就是金字塔顶。

**何时用。** 开篇/引子。短视频里这就是"钩子"。

**变体。** 标准式(S-C-Q-A)、开门见山式(A-S-C)、突出忧虑式(C-S-Q-A,先抛冲突)。

**模板。**
```
S:我们都________(共识)
C:但是________(变化/问题)
Q:那么________?(问题)
A:答案是________(主张)
```
对应版式:`scqa`。

---

## 3. MECE（分类原则：相互独立,完全穷尽）

**是什么。** Mutually Exclusive(各项之间不重叠) + Collectively Exhaustive(合起来无遗漏)。它是"归类分组"的质检标准,本身不是叙事结构。

**何时用。** 每当你把一件事拆成几个要点/维度时,都用它检查:有没有重叠?有没有漏掉?

**常用切分法。**
- 按流程/时间:before → during → after
- 按结构/要素:人 / 货 / 场;时间 / 空间 / 同伴
- 按二分:内部 vs 外部、主观 vs 客观
- 按公式:利润 = 收入 − 成本

**经验法则。** 要点数量控制在 **3 个**最佳,最多不超过 7 个(「神奇数字 7±2」)。
对应版式:`parallel`(并列要点) / `matrix`(2×2)。

---

## 4. 空雨伞（事实 → 解读 → 行动）

**是什么。** 麦肯锡经典思考/表达框架,从观察推进到对策:
- **空(事实 / Air)** —— 抬头看天:客观事实、观察到的现象。
- **雨(解读 / Rain)** —— 判断要下雨:基于事实的分析与推断。
- **伞(行动 / Umbrella)** —— 所以带伞:据此应采取的行动/建议。

**何时用。** 把"现象"推进到"对策"时;给建议、做决策、提行动方案时。它强制你"先有事实再有判断,先有判断再有行动",避免拍脑袋。

**模板。**
```
空(事实):我们观察到________
雨(解读):这说明________
伞(行动):因此应该________
```
对应版式:`air-rain-umbrella`。

---

## 5. PREP（单个论点的展开）

**是什么。** Point(观点) → Reason(理由) → Example(例子) → Point(重申)。用于把"一个"论点讲透,首尾呼应。

**何时用。** 展开金字塔里某一组支撑理由时;一页之内论证一个点时。

**模板。**
```
P:我的观点是________
R:因为________
E:比如________
P:所以________(重申)
```
没有专门版式,通常融进 `parallel` 单条或一页正文里。

---

## 6. What–Why–How（黄金圈 / 2W1H）

**是什么。** 是什么 → 为什么 → 怎么做。最朴素的讲解三段式。

**何时用。** 介绍一个概念、方法或产品;听众需要"先懂再信再做"时。Why 在前(黄金圈 Why-How-What)更有感染力,适合理念驱动的开场。

对应版式:可用 `parallel`(三栏) 或 `process` 承载。

---

## 7. 信息组织的四种基本关系

给一组要点排序时,先想清它们之间是哪种关系——这决定了用哪种版式:

| 关系 | 含义 | 适合版式 |
|------|------|----------|
| **并列** Parallel | N 个平级、同类的要点 | `parallel` / `matrix` |
| **递进** Progressive | 层层深入、由浅入深、按时间推进 | `process` / `pyramid` |
| **对比** Contrast | A vs B、现状 vs 目标、正确 vs 错误 | `comparison` |
| **总分** Whole-Part | 先总后分 / 先分后总 | `pyramid` + `parallel` |

---

## 速查：从"想表达什么"到"选哪个结构 / 版式"

| 你要表达 | 用结构 | 用版式 |
|----------|--------|--------|
| 开篇引出主题、制造张力 | SCQA | `scqa` |
| 抛出全篇的核心主张 | 金字塔顶 | `governing` |
| 展示"结论 + 几组理由"的整体逻辑 | 金字塔 | `pyramid` |
| 几个平级要点/维度(已 MECE 校验) | 并列 + MECE | `parallel` |
| 两个方案/状态的差异 | 对比 | `comparison` |
| 按两个维度给事物分类定位 | 矩阵 + MECE | `matrix` |
| 从现象推到该做什么 | 空雨伞 | `air-rain-umbrella` |
| 一套有先后的步骤/闭环 | 递进/流程 | `process` |
| 收尾,给出可执行的行动 | 结论先行 | `takeaway` |

> 一篇 6–10 页的短视频演示,典型骨架:`cover → scqa → governing → pyramid → (parallel / comparison / matrix 选 1–2) → air-rain-umbrella 或 process → takeaway`。不必每种都用,按内容取舍。
