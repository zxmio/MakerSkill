# 麦肯锡表达演示页生成器 (McKinsey-style Deck)

把一段**短视频逐字稿 / 口播稿**,改造成「结论先行、逻辑清晰」的 **9:16 竖版结构化演示页面(HTML)**,用于短视频讲解演示。

核心不是"把稿子搬上屏幕",而是先用麦肯锡表达结构**重组逻辑**,再落成简约大方的演示页。

与 AI 生图做 PPT 不同:**本技能产出的是 HTML 页面**——文字 100% 准确、可随时改字调色、自带翻页交互,适合录屏讲解。工作流是「理解需求 → 选版式 → 组装 → 自检」。

## 资源

- 表达结构详解:`references/mckinsey-structures.md`(金字塔 / SCQA / MECE / 空雨伞 / PREP / Action Title 等,含何时用、模板、正反例)
- HTML 模板与版式组件库:`assets/template.html`(一个可直接预览的完整示例 + 10 种版式 `<section>`)

开始前**务必先读** `references/mckinsey-structures.md`,再打开 `assets/template.html` 了解每种版式的 HTML 结构。

## 工作流程

### 1. 拆解逐字稿,提炼"金字塔顶"
通读逐字稿,回答一个问题:**这段话最想让人记住的一句结论是什么?(So what?)** 这句话就是中心论点(Governing Thought),整篇围绕它组织。口播稿往往结论藏在中间或结尾,要主动把它"提"到最前面。

### 2. 设计 Storyline(最关键的一步)
用麦肯锡结构搭出整篇骨架,**为每一页写一句结论式 Action Title**:
- 开场用 **SCQA**(情境-冲突-疑问-答案)引出主题。
- 用 **金字塔原理**确定"中心论点 + 3 组支撑理由"。
- 用 **MECE** 检查支撑理由/要点有没有重叠或遗漏(数量控制在 3 个,最多 7)。
- 局部展开按内容选 **空雨伞 / PREP / 对比 / 流程**。
- 收尾给出可执行 **行动(Takeaway)**。

写完后做 **Storyline 自检**:把所有页的 Action Title 单独抽出来顺次读一遍,如果连起来是一段通顺、有说服力的话,逻辑就立住了;读着别扭就回去调结构。

典型骨架(6–10 页,按需取舍,不必每种都用):
```
cover → scqa → governing → pyramid → (parallel / comparison / matrix 选 1–2)
      → (air-rain-umbrella 或 process) → takeaway
```

### 3. 为每页选版式
根据每页要表达的"信息关系",从下表选版式(详见 `references` 速查表):

| 版式 (data 注释名) | 用途 | 信息关系 |
|------|------|----------|
| `cover` | 封面:主张式大标题 + 副标题 | — |
| `scqa` | 开场:情境-冲突-疑问-答案 | 导入 |
| `governing` | 核心论点页:一句话金句 | 结论先行 |
| `pyramid` | 逻辑总览:1 主张 + 3 支撑 | 总分 / 以上统下 |
| `parallel` | 并列要点(MECE,3 栏) | 并列 |
| `comparison` | 对比:A vs B / 现状 vs 目标 | 对比 |
| `matrix` | 2×2 矩阵:按两维度分类定位 | 并列 + 分类 |
| `air-rain-umbrella` | 空雨伞:事实→解读→行动 | 递进 |
| `process` | 流程:有先后的步骤/闭环 | 递进 |
| `takeaway` | 结论:核心主张 + 行动清单 | 结论先行 |

### 4. 组装 HTML
基于 `assets/template.html`:
1. 复制模板为新文件(命名见下)。
2. 删掉用不到的 `<section>`,把需要的版式 `<section>` 按 storyline 顺序排列。
3. 逐页填入内容:`<h2 class="action">` 写 Action Title,版式内部按其 HTML 结构填要点。
4. 每个 `<section>` 的 `data-part` 改成它所属的逻辑模块名(显示在页眉左上)。
5. 顶部 `.header .topic` 和底部 `.footer .src` 改成本篇主题/署名。
6. 检查每页 `.anim` 元素的 `--d` 动画延迟是否顺次递增(0.05s 起,每条 +0.1~0.12s)。
7. **更新页码总数**:模板 JS 会自动数页数,无需手改;但确认 `total` 显示正确。

### 5. 预览与交付
```bash
open "<输出路径>"
```
告诉用户文件路径、共几页、用了哪些麦肯锡结构;说明交互方式(`← →`/空格翻页、点击画面左右半区、底部圆点)。

## 视觉规范（简约大方·麦肯锡专业风）

模板已内置,改内容时保持这套语言,不要破坏:
- **配色三色制**:白底 + 墨蓝(`--ink #0A1F33` / `--navy #0A2540`)正文 + 单一强调蓝(`--blue #1F6FEB`)。强调色**只给关键结论和数字**,不要整页铺色。红色(`--red`)极少用,仅在"冲突/警示"点睛。
- **留白充足**:信息密度宁少勿多。一页一个核心观点,要点 3 个最佳、最多 7 个;超了就拆页。
- **Action Title 左对齐**置顶,是完整结论句(见 references 第 0 节)。
- **字体**:正文思源黑体/PingFang;编号、英文小标签、数字用 Inter(等宽感增强报告气质);核心金句可用 Noto Serif SC 衬线增加分量。
- **动画克制**:仅轻微上浮淡入,顺次出现,不要花哨特效。
- **9:16 固定**,用容器查询单位(`cqh`/`cqw`)自适应,录屏不会错位。

## 文件命名与输出位置

- 命名:`yyyy-mm-dd-mckinsey-<主题>.html`
- 默认输出到桌面 `~/Desktop/`,或用户指定目录。

## 注意事项

- **先重组逻辑,再排版**。本技能的价值在结构;直接把逐字稿分段贴上去 ≠ 结构化表达。
- **Action Title 必须是结论句**,不能是名词标签(这是麦肯锡风格的命门)。
- **MECE 校验**:每组要点检查重叠与遗漏;数量 3 个最佳。
- **字体走 Google Fonts 在线加载**:录屏前确保联网,否则回退系统字体(不影响排版)。用户要完全离线一致,可改用本地 PingFang 或内嵌字体。
- **内容取舍**:6–10 页为宜。逐字稿信息过多时,只保留服务于中心论点的内容,其余砍掉——"完全穷尽"指逻辑维度无遗漏,不是把所有话都塞进去。
- 中文表达保持口语转书面的"结论化"语气:短句、有力、能独立读懂。

## 对外演示文案铁律（生成页面内容时必须遵守）

**1. 页面上绝不出现技能的英文 ID。** 一律用中文业务语言描述这一步在干什么。

| 页面上写 | 页面上不写 |
|---|---|
| 转写提炼 | ~~meeting-digest~~ |
| 写发售信 | ~~product-launch-letter~~ |
| 出详情页 | ~~product-detail-page~~ |
| 结构化演示 | ~~mckinsey-deck~~ |

理由：英文技能名对非技术听众是纯噪音——既不说明这一步在干什么，又制造「这是技术活」的距离感。**听众要知道的是「这一步产出什么」，不是「这个技能叫什么」。**
例外：「Skill」「CLI」「Agent」这类已成通用说法的概念术语可保留。

**2. 不放副标题，不放底部金句——页面只留骨头。**

- **标题下的一句话副标题**：多数是主体内容的重复，标题区堆两行会削弱主标题的视觉权重。真必要就放进主体的引言横条，不要挂在标题下。
- **底部金句条**：那是讲师嘴里要说的话，印在页面上等于把逐字稿贴出来；每页都有就退化成页脚装饰，听众自动跳过。
- **收益**：底部横条占页面高度 12–15%，副标题再占一行，去掉后主体多出近两成空间，字号整体大一档，投影可读性直接改善。
- **唯一例外**：行动号召页（留资、报名、二维码）可保留一句收口，因为那句话本身就是行动指令。
- **金句页 / 引言页不放引号装饰**：超大引号是纯装饰，有署名就已说明这是引语，它不增加信息却占掉顶部一大块。去掉后金句能更大、位置更居中。同理不放装饰性星标、灯泡、旗帜。
- **单行文字不超过 30 字**：文字发虚的根因常是一行塞太多字，模型只能压小字号。解决办法不是「字大一点」，而是**把长句拆成短句或标签**——结构改了字号自然上来。

**3. 标题一律名词化。** 主标题、区块标题、步骤名全部用名词或名词短语，不要自然语言句子。表达力强的那句降为副标题。

**名词化不等于硬凑后缀——自然度优先于工整度。** 不要为了让几个标题对仗而生造词：「客户沟通归档**线**」「需求收集**流**」这类汉语里不存在的搭配读起来一定别扭。判断方法：把这个词单独念一遍，如果你在别处从没听过这个搭配，就是生造的。「生产线」「流水线」是既有词可以用，「归档线」不是。**宁可四个标题长短不一，也不要为了排比造一个不存在的词。**

**4. 横向栏数不超过 4。** 每多一栏字号压小一档，超过 4 栏正文在投影上会发虚。信息多就分两页，或把「输入/产出」改成上下横条。
